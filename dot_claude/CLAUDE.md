# 開発指針

一貫性、可読性、保守性を重視しシンプルな実装を心がける。
不明瞭な指示は質問を行い明確にする。
公式ドキュメント等の1次ソースをまず調査する。
非自明な変更では、実装に着手する前にインターフェース仕様（シグネチャ・型・エラー仕様など）を確定する。

# 実装・レビュー・テスト方針

設計・計画・インターフェース仕様（シグネチャ・型・エラー仕様など）の確定はメインが行い、確定した仕様に基づく実装は `implementer` に委譲する。
テストは実装をなぞらず仕様・インターフェースに対して書くものであり、実装完了を待つ必要はない。インターフェース仕様確定後は、`implementer` と `test-author` を Agent ツール（`run_in_background: true`）で並行起動する。
実装担当・レビュアー・テスト担当には仕様・変更の意図・対象ファイル・制約を必ず渡す（隔離コンテキストには要約しか伝わらないため）。`code-reviewer` には加えて差分（`git diff` の出力）をプロンプトに含める（Bash を持たず自力で差分を取得できないため）。
`code-reviewer` によるレビューは実装とテストの両方が完成してからまとめて行う（レビューは実装完了に依存するため並行不可）。自己正当化バイアスを排除するため、実装を書いたコンテキストとは別エージェントに行わせる。
小さな変更・自明な修正では上記を省略し、メインが直接実装してよい（オーバーヘッド回避）。
`code-reviewer` のレビュー結果は会話に提示する（サブエージェントの返り値は tool result として親に返るだけでユーザーの画面には出ず、Ctrl+O でも展開されないため）。
